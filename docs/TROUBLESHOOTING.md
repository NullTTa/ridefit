## T1. 호환성 판정 API의 간헐적 500 (MariaDB 1020)

- **문제**: 운영에서 `GET /api/parts/{id}/check`가 가끔 500을 냈고, 부품 상세의 판정 칸이 사라졌습니다. 로컬(MySQL 8)과 테스트(H2)에서는 한 번도 재현되지 않았습니다.
- **원인**
  - 서버 로그: `Record has changed since last read in table 'recent_part_check'` (MariaDB 오류 1020), 실패한 SQL은 `insert into recent_part_check` 하나.
  - nginx 접근 로그: 500이 난 두 번 모두 같은 초에 같은 부품의 `GET /api/parts/{id}?myVehicleId=` 요청이 함께 있었습니다. 이 요청은 부품의 조회수를 바꿉니다.
  - 판정 트랜잭션은 부품을 먼저 읽은 뒤 마지막에 최근 확인 기록을 INSERT합니다. INSERT할 때 외래키 확인이 부품 행을 잠그고 다시 읽는데, 그 사이 조회수 증가가 부품 행을 바꿨으면 MariaDB 11.8의 스냅샷 격리 검사가 오류를 냅니다.
- **해결**
  - 판정(`CompatibilityCheckService.check`)은 읽기 전용으로 두고, 기록은 별도 빈 `RecentPartCheckRecorder`가 `REQUIRES_NEW` 트랜잭션에서 `getReferenceById`로 바로 INSERT합니다. 이 트랜잭션의 첫 문장이 INSERT라 비교할 스냅샷이 없습니다.
  - 기록이 실패해도 판정 결과는 200으로 돌려주고, 로그에는 부품 id와 오류 종류만 남깁니다(회원 정보 없음).
  - DB 전역 설정(`innodb_snapshot_isolation`)은 다른 서비스와 공유하는 RDS라 바꾸지 않았습니다.
- **확인 (2026-10-15)**
  - `CompatibilityCheckServiceTest`·`PartViewAndCheckTest`: 기록 성공 / 기록 실패에도 같은 판정 200.
  - 운영 배포 후 검증 15/15 통과, 검증 시점까지 서비스 로그의 1020 오류 0건, nginx 5xx 0건.
  - 남은 위험: 충돌이 다시 나면 500 대신 경고 로그가 남고 그 확인 기록 한 건만 빠집니다.

## T2. 조회수 2배 집계와 동시 요청 누락

- **문제**: 차량을 고른 상태로 부품 상세를 열면 조회수가 2씩 올랐습니다. 조회수 증가가 "읽고 +1 해서 저장" 방식이라 동시 요청에서는 값이 빠질 수 있었습니다(T1의 원인이기도 함).
- **원인**: 화면이 일반 상세와 차량 기준 상세를 모두 요청했고, 두 요청이 각각 조회수를 기록했습니다.
- **해결**
  - `PartRepository.incrementViewCount` / `incrementFitSelectionCount`: `update … set view_count = view_count + 1` (조회수와 장착 시도 수는 따로 셈).
  - 상세 API는 차량 확인을 먼저 해서 403/404로 끝나는 요청은 조회로 세지 않습니다. 증가 뒤 부품을 다시 읽어 응답에 저장된 값을 보냅니다.
  - 화면(`PartDetail.jsx`)은 차량 기준 상세 하나만 요청하고, 그 차량이 내 것이 아닐 때(403/404)만 차량 없이 다시 받습니다.
  - 개발 모드에서 요청이 두 번 보이는 것은 React StrictMode의 이중 실행이며, 운영 빌드에서는 한 번인 것을 확인했습니다.
- **확인 (2026-10-15)**: 예전 방식으로 되돌리면 동시성 테스트가 실패하고, 수정 후에는 30번 동시 기록에 +30. 운영에서 차량 선택 상태 상세 요청 1번·조회수 +1, 403/404 미집계. 수정 전에 2배로 쌓인 운영 조회수는 보정하지 않았습니다.

## T3. 부품을 골라도 차량 이미지가 바뀌지 않는 것처럼 보임

- **문제**: 휠·윈드스크린을 골라도 왼쪽 차량에 변화가 없다는 사용자 피드백.
- **원인** (운영과 같은 버전을 로컬에서 재현)
  - 휠은 2025년식에만 호환이 등록되어 있는데, 부품 상세의 "장착해보기"가 2023년식 차량에도 보였습니다. 들어가면 "호환 확인 안 됨" 안내만 나오고 아무것도 그려지지 않았습니다.
  - 윈드스크린은 그려지고 있었지만 작고 투명해서 변화가 거의 보이지 않았습니다.
  - 모바일에서는 목록의 버튼을 누르는 순간 차량이 화면 밖에 있었습니다.
  - 선택하는 즉시 겹쳐 그리는 방식이라 "무엇이 적용된 결과인지" 구분할 수 없었습니다.
- **해결**: 선택과 결과를 분리하고 [입혀보기] 버튼으로 결과를 만들게 했습니다. 선택이 바뀐 결과는 흐리게 표시하고 저장을 막습니다. 차량 선택 목록에 차량별 호환 여부를 표시했고, 모바일 하단 [입혀보기] 바를 추가했습니다. 자세한 동작은 [FEATURE_FLOWS.md](FEATURE_FLOWS.md).
- **확인 (2026-10-15)**: 로컬 브라우저 101/101(호환 부품 53개를 하나씩 입혀 보고 결과 이미지의 실제 픽셀 변화 확인), 운영 회귀 30/30.

## T4. 이미지 없는 부품을 고른 차량에서 잘못된 안내

- **문제**: PCX에서 부품을 고르면 무대가 "아직 입혀보기 전"이라고 안내했지만, 실제로는 입혀볼 수 없는 차량이었습니다. 부착 위치 표시도 사라졌습니다.
- **원인**: PCX는 부착 좌표만 있는 배치 정보가 있어서 "배치 정보 없음"이 아닌 "그릴 이미지 없음"으로 분류되는데, 무대가 이 경우를 따로 처리하지 않았습니다.
- **해결**: 결과 이미지가 없을 때는 이미지 없는 선택 부품의 부착 위치를 표시하고, "입혀보기를 아직 지원하지 않아요"로 안내합니다(`FitResultStage.jsx`).
- **확인**: 로컬 PCX·사용자 사진 차량 미지원 안내 테스트(1280·390px), 운영 PCX 확인.

## T5. 저장 결과가 다른 회원의 결과로 열림

- **문제**: 새 회원이 저장해도 내 저장 목록에 아무것도 생기지 않고 다른 회원의 결과가 열렸습니다(신규 회원 시나리오 테스트에서 발견).
- **원인**: 저장 결과 재사용 키가 부품 조합만 보고 있었습니다.
- **해결**: 재사용 범위를 "같은 회원 + 같은 차량 + 같은 조합"으로 좁혔습니다(`AiFitResultRepository.findFirstByCacheKeyAndRequestedByMemberIdAndMyVehicleId…`).
- **확인**: `CompositeFitTest`에 회원·차량별 분리 검증을 추가했습니다.

## T6. 배포 JAR에 로컬 설정 파일이 들어감

- **문제**: `gradlew bootJar` 결과물에 로컬 비밀값 파일(`application-local.properties`)이 포함됩니다(`.gitignore`로 저장소에는 올라가지 않지만 빌드에는 들어감).
- **해결 (배포 절차)**: 배포용 JAR은 그 항목 하나만 뺀 사본을 만들어 쓰고, 나머지 항목의 내용·압축 방식이 원본과 같은지, 해당 파일이 없는지 확인한 뒤 올립니다. 업로드는 임시 파일 이름으로 하고, 서버에서 전체 SHA-256과 크기를 대조한 뒤에만 교체합니다(업로드 중 연결이 끊긴 적이 있음).
- **개선 예정**: 빌드 설정에서 `bootJar`가 로컬 설정 파일을 제외하도록 바꾸는 것.

## T7. 운영 DB에서 Hibernate 방언 인식 실패

- **문제**: 운영 DB(AWS RDS MariaDB 11.8)에 MySQL 드라이버로 연결하면 시작할 때 방언 자동 인식이 실패했습니다(`Unknown column 'RESERVED'`).
- **해결**: 운영 환경 변수로 `SPRING_JPA_DATABASE_PLATFORM=org.hibernate.dialect.MariaDBDialect`를 지정했습니다. 시작 로그의 "Could not obtain connection metadata" 경고는 이 때문에 남는 기존 경고입니다.

## T8. 정비소 상세 지도가 안 보임

- **원인 1**: Kakao 지도 JavaScript 키는 등록한 도메인에서만 동작합니다. 개발 서버 포트가 바뀌면(`5173` → `5174`) `domain mismatched`로 지도가 뜨지 않습니다. 그래서 Vite 개발 서버는 다른 포트로 넘어가지 않도록 `strictPort`로 고정했습니다.
- **원인 2**: 매장이 하나인 상세 화면에서 Kakao `LatLngBounds`에 없는 `getCenter()`를 호출하고 있었습니다. 그 매장 좌표를 중심으로 쓰도록 고쳤습니다(`KakaoServiceMap.jsx`).

## T9. 개발 환경 참고 사항

- Windows에서 백그라운드로 띄운 `gradlew bootRun`이나 `npx vite`를 종료해도 자식 java/node 프로세스가 포트를 계속 쓰는 경우가 있습니다. 포트 기준으로 프로세스를 확인해 종료합니다.
- Git Bash에서 한글이 든 JSON을 `curl -d`로 보내면 본문이 깨져 401처럼 보일 수 있습니다. 파일로 저장해 `--data-binary @file.json`으로 보냅니다.
