# 알려진 한계와 향후 계획

## 현재 한계

### 장착 이미지
- 검증한 2D 장착 레이어가 있는 부품은 Super Cub 110 기준 앞바구니(H2C), 사이드백(한 쌍), 순정 스타일 스테인리스 머플러, 수제 스포크 휠뿐이다.
  나머지는 "간이 미리보기"다(2023 JA59 기준 47개 중 상품 사진 근사치 7개, 간이 일러스트 37개). 상품 사진은 대부분 3/4 각도 제품컷이라 측면 사진 위에서 떠 보이거나 크기·각도가 다르고, 일러스트는 같은 카테고리면 같은 그림이며 실제 제품 모습이 아니다. 360° 보기에는 간이 미리보기가 없다. 저장 이미지는 부품 8개까지(서버 한도).
- 다른 차종(PCX, NMAX, Address, Burgman, Tricity, Vino, Cygnus)은 부착 지점 좌표만 있고 부품 레이어는 없다. NMAX는 좌표가 있는 카테고리가 적어 나머지 부품 배지가 무대 중앙에 모인다(겹치지 않게 하나로 묶임).
- 아주 작은 무대(예: 1280×600 데스크톱의 고정 미리보기)에서는 묶인 배지가 핸들 주변 차체를 일부 가린다.
- 360° 레이어는 Super Cub 110의 앞바구니·사이드백·머플러·휠만 있다.
- 사용자가 직접 올린 차량 사진에는 레이어 배치를 적용하지 않는다(구도를 알 수 없음).

### 데이터
- 2025 Super Cub 110(JA59)의 호환 부품은 6개다(모두 근거 메모 있음): 검증 레이어 3(H2C 앞바구니, 사이드백 한 쌍, 수제 스포크 휠) +
  상품 사진 근사치 3(컵홀더 사이드백, H2C 윈드스크린, KITACO 캐리어). 레이어가 준비된 머플러(순정 스타일 스테인리스)는 2025 호환 근거가 없어
  추가하지 않았다 - 2025 연식에서는 머플러를 고를 수 없다(2021 JA44 / 2023 JA59는 가능). 간이 일러스트로만 그려지는 부품은 2025 연식에 없다.
- 판매처 가격은 확인일 기준이며 실시간이 아니다. 품절 여부는 데이터로 관리하지 않는다.
- 가격: 가격이 없는 부품은 "가격 정보 준비중"으로 표시하고 구매 버튼을 숨긴다. 코드 시더는 더 이상 출처 없는 가격을 넣지 않는다.
  - **이 프로젝트의 개발 DB(2026-10-14 정리 완료):** 백업 후 출처 없는 부품 가격 35건(id 1~30, 32~36)을 비우고, "리어 확장 캐리어 (Cub 110)"에
    잘못 연결된 다른 상품(스티커) 판매처 1건을 지웠다. 지금 가격이 있는 부품은 판매처 근거가 있는 7개뿐이다.
  - **예전 시드로 만든 다른 DB:** 시더는 같은 이름의 부품이 있으면 그대로 두므로 출처 없는 가격이 남아 있을 수 있다. 그 가격은 일반 가격처럼 보이고
    Toss 테스트 결제 금액에도 쓰이므로, 백업 후 별도로 정리해야 한다.
- 예시 판매처(`example-shop.test`) 23건은 DB에 남겨 두었다. 화면에서 "예시 데이터 · 실제 판매처 아님"으로 표시되고, 링크가 없으며, 최저가 비교와 참고 가격에서 빠진다.
- 호환 근거: "호환가능"인데 근거 메모가 없는 데이터가 개발 DB 기준 89건이다(주로 JA44 기준 데모 데이터를 2023 JA59에도 넣은 항목).
  화면에서는 "호환 근거 미확인"(초록이 아닌 회색 표시)과 "구매 전 판매처나 제조사에 장착 가능 여부를 확인" 안내로 구분한다.
  - 장착 후보에서는 빼지 않는다(입혀보기·저장은 그대로 가능). 서버의 저장 검증도 호환가능/브라켓필요만 확인하므로 미확인 데이터로도 저장된다.
  - 근거 메모가 있는 데이터도 일부는 시드 작성 당시의 데모 값이다(예: 2023 JA59 머플러의 "정품 브라켓 포함"은 JA44 기준 메모). 메모가 있다고 실제 장착이 보장되지는 않는다.
  - DB의 호환 판정은 바꾸지 않았다. 근거가 확인되지 않은 행을 "확인 필요" 같은 별도 상태로 옮기려면 데이터 마이그레이션(백업 후)과 관리자 화면 수정이 필요하다.

### 기능
- 결제는 Toss Payments 테스트 모드만 지원한다.
- 외부 이미지 생성("장착한 모습 만들기")은 API 키가 있을 때만 동작하는 선택 기능이고, 결과는 참고용 이미지다.
- Windows에서 저장 이미지 파일을 다른 요청이 읽고 있는 순간 삭제하면 파일 삭제가 실패할 수 있다(DB 행은 삭제되고 서버 로그에 경고가 남음).

### 운영
- 2026-10-15 수정 전까지 차량을 고른 부품 상세 조회가 2번씩 집계되었다. 기존 조회수는 보정하지 않았다(인기 배지·추천 순위가 그만큼 영향을 받았을 수 있음).
- 최근 확인 기록은 판정과 분리되어, DB 충돌이 나면 그 기록 한 건이 빠지고 서버 로그에 경고가 남는다(판정 결과는 정상 반환).
- nginx가 `index.html`에 캐시 정책(`Cache-Control`)을 보내지 않아, 배포 직후 일부 브라우저가 강력 새로고침 전까지 이전 화면을 보여 줄 수 있다. 이전 번들 파일은 서버에 남겨 두어 화면이 깨지지는 않는다.
- `gradlew bootJar` 결과물에 로컬 설정 파일이 포함되어, 배포 때 그 항목을 뺀 사본을 따로 만든다([TROUBLESHOOTING T6](TROUBLESHOOTING.md#t6-배포-jar에-로컬-설정-파일이-들어감)).
- 저장한 결과 이미지는 서버 디스크(`uploads/`)에 있고 별도 이미지 저장소·백업 자동화는 없다.

## 향후 계획
- 차종별 측면 사진 기준 부품 레이어 확대(PCX 등) 및 레이어 제작 도구 정리
- 판매처 가격·판매 상태 재확인 주기화, 출처 없는 가격 데이터 정리
- 저장한 장착 모습 비교 보기(두 조합 나란히 보기)
- `index.html` 재검증(`no-cache`) / 해시 번들 장기 캐시 정책 적용
- 빌드 설정에서 로컬 설정 파일 제외, 저장 이미지 저장소 분리와 백업 자동화
