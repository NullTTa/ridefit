# 알려진 한계와 향후 계획

## 현재 한계

### 장착 이미지
- 2D 레이어가 준비된 부품은 Super Cub 110 기준 앞바구니(H2C), 사이드백(한 쌍), 순정 스타일 스테인리스 머플러, 수제 스포크 휠 등 일부다.
  나머지 부품은 부착 지점 + "장착 이미지 준비 중" 배지로 표시한다.
- 다른 차종(PCX, NMAX, Address, Burgman, Tricity, Vino, Cygnus)은 부착 지점 좌표만 있고 부품 레이어는 없다. NMAX는 좌표가 있는 카테고리가 적어 나머지 부품 배지가 무대 중앙에 모인다(겹치지 않게 하나로 묶임).
- 아주 작은 무대(예: 1280×600 데스크톱의 고정 미리보기)에서는 묶인 배지가 핸들 주변 차체를 일부 가린다.
- 360° 레이어는 Super Cub 110의 앞바구니·사이드백·머플러·휠만 있다.
- 사용자가 직접 올린 차량 사진에는 레이어 배치를 적용하지 않는다(구도를 알 수 없음).

### 데이터
- 2025 Super Cub 110(JA59)에는 레이어가 준비된 머플러(순정 스타일 스테인리스)의 호환 데이터가 없다. 근거 없이 호환을 추가하지 않아
  2025 연식에서는 앞바구니 + 사이드백까지만 이미지로 장착된다(2021 JA44 / 2023 JA59는 세 부품 모두 가능).
- 판매처 가격은 확인일 기준이며 실시간이 아니다. 품절 여부는 데이터로 관리하지 않는다.
- 개발용 로컬 DB에는 예전 시드의 출처 없는 가격과 예시 판매처(`example-shop.test`)가 남아 있을 수 있다. 예시 판매처는 화면에서 "예시 데이터"로 표시되고 최저가 비교에서 빠진다.
  출처 없는 가격 정리는 DB 백업 후 별도로 진행해야 한다(코드 시더는 더 이상 출처 없는 가격을 넣지 않음).
  시더는 같은 이름의 부품이 있으면 그대로 두므로, 이미 가격이 들어간 DB는 다시 실행해도 가격이 지워지지 않는다.
- 출처 없는 가격이 남은 DB에서는 그 가격이 부품 목록·상세에 일반 가격처럼 보이고 Toss 테스트 결제 금액에도 쓰인다.
- 2026-10-14 개발 DB 정리: 백업 후 출처 없는 부품 가격 35건(id 1~30, 32~36)을 비우고, "리어 확장 캐리어 (Cub 110)"에 잘못 연결된 다른 상품(스티커) 판매처 1건을 지웠다.
  예시 판매처(`example-shop.test`) 23건은 "예시 데이터"로 구분되어 있어 남겨 두었다. 예전 시드로 만든 다른 DB에는 같은 데이터가 남아 있을 수 있다.
- 호환 데이터 일부(JA44 기준 데모 데이터를 2023 JA59에도 넣은 항목 등)는 근거 메모가 없지만, 화면에서는 근거가 있는 호환과 같은 "호환가능"으로 표시된다.

### 기능
- 결제는 Toss Payments 테스트 모드만 지원한다.
- 외부 이미지 생성("장착한 모습 만들기")은 API 키가 있을 때만 동작하는 선택 기능이고, 결과는 참고용 이미지다.
- Windows에서 저장 이미지 파일을 다른 요청이 읽고 있는 순간 삭제하면 파일 삭제가 실패할 수 있다(DB 행은 삭제되고 서버 로그에 경고가 남음).

## 향후 계획
- 차종별 측면 사진 기준 부품 레이어 확대(PCX 등) 및 레이어 제작 도구 정리
- 판매처 가격·판매 상태 재확인 주기화, 출처 없는 가격 데이터 정리
- 저장한 장착 모습 비교 보기(두 조합 나란히 보기)
- 배포 환경 구성(이미지 저장소 분리, 데모 주소 공개)
