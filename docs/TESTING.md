# 테스트 및 검증 결과

## 실행 방법

```powershell
.\gradlew.bat test --rerun        # 백엔드 단위/통합 테스트(H2 인메모리, test 프로필)
cd frontend; npm run lint; npm run build
```

브라우저 회귀 검증은 Playwright(headless Chromium) 스크립트로 로컬 서버(8080 + Vite 5173)에 붙여 실행했다.
스크립트는 저장소에 포함하지 않았다(작업용 임시 폴더). 아래 표는 그 스크립트가 확인한 항목이다.

검증 원칙
- 외부 이미지 생성 API 호출 0회: 생성 요청(`POST /api/ai-fit`)은 브라우저에서 가로채 서버로 보내지 않았고, 서버 로그의 생성 요청 기록도 0건.
- 기존 회원 데이터는 바꾸지 않음: 신규 시나리오는 새 테스트 계정으로 하고, 끝나면 저장 결과 삭제(앱 기능) + 탈퇴로 정리.
- 부품 인기 통계: "장착 시도 집계" 요청은 브라우저에서 가로채 서버로 보내지 않았다. 부품 상세 조회수는 같은 URL을 한 번만 서버에서 받았다.

## 이번 검증에서 발견해 고친 문제

- 다른 회원이 같은 차종·연식·부품 조합을 먼저 저장했으면, 새 회원의 [현재 모습 저장]이 그 회원의 결과를 돌려받아 내 저장 목록에 아무것도 생기지 않았다.
  저장 결과 재사용을 "같은 회원 + 같은 차량"으로 좁혔다(`AiFitService.saveComposite`, `AiFitResultRepository`).

- Toss 실결제(테스트 키 없이 화면 안내만 확인).
- 카카오 지도는 로컬 키/도메인 설정에 따라 다름(레이아웃만 확인).
